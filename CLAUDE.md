# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A **source-of-truth** for personal AI CLI skills, managed by the
[`skillshare`](https://github.com/runkids/skillshare) CLI (by `runkids`).
It is NOT an application — there is no build / lint / test pipeline. The
"product" is the skill folders themselves, which `skillshare sync` fans out as
symlinks into ~60 AI CLI tools' skill directories
(`~/.claude/skills/`, `~/.cursor/skills/`, `~/.codex/skills/`, etc.).

Companion repos:
- [`runkids/skillshare`](https://github.com/runkids/skillshare) — the CLI tool itself
- [`runkids/my-skills`](https://github.com/runkids/my-skills) — author's reference personal-skill source; this repo's layout follows its conventions
- [`elf-express/org-skills`](https://github.com/elf-express/org-skills) — team-wide standards, cloned into `_elf-dev/` (see "Tracked repos" below)

## Repo layout

```
skillshare-source/
├── frontend/{react,vue,design}/<skill>/        # personal skills, category-grouped
├── backend/<skill>/
├── desktop/<skill>/
├── web-dev/<skill>/
├── utils/<skill>/
├── skillshare/                  # skillshare meta tool — excluded via .skillignore
├── _elf-dev/                    # tracked external repo (own .git) — gitignored
├── .skillignore                 # like .gitignore but for skill sync
├── .metadata.json               # skillshare-managed; tracks _elf-dev source + skillshare meta tool version
├── .gitignore                   # only excludes _elf-dev/ and .DS_Store
└── README.md
```

Each skill is a folder containing at minimum a `SKILL.md` (the spec/prompt
loaded by the AI tool); optional `references/`, `assets/`, `scripts/`,
`rules/`, `components/`, etc. depending on skill type.

### Nested paths auto-flatten on sync

`frontend/react/shadcn/` → `~/.claude/skills/frontend__react__shadcn/`. The
`__` separator is generated by `skillshare`; **never** name a skill folder
with `__` yourself. Use the category-folder structure for new skills.

### Tracked repos (`_elf-dev/`)

`_elf-dev/` is a separate git clone of `elf-express/org-skills` (branch `dev`),
listed in `.metadata.json` with `tracked: true`. It is `.gitignore`d so its
content does **not** ship in this repo's commits — instead, on a fresh clone,
`skillshare pull` reads `.metadata.json` and re-clones it automatically.

**Never** `git add` files under `_elf-dev/`. To update it, run
`skillshare update _elf-dev` (or `skillshare update --all`).

### `.skillignore`

Listed folders stay in the repo but never sync to targets. Used to keep
non-skill assets (e.g., the `skillshare` meta tool installed via
`skillshare install runkids/skillshare/skills/skillshare`) in-tree without
polluting downstream AI CLIs.

## Branch workflow

Three branches kept on the same commit via fast-forward:

| Branch | Role |
|---|---|
| `dev`     | **primary development branch — make commits here** |
| `master`  | promoted from `dev` via `--ff-only` |
| `release` | promoted from `master` via `--ff-only` |

Standard promote sequence after committing on `dev`:

```bash
git push origin dev
git checkout master  && git merge --ff-only dev && git push origin master
git checkout release && git merge --ff-only dev && git push origin release
git checkout dev
```

Do **not** commit directly on `master` — it breaks the FF chain and the only
recovery is force-pushing.

## Common operations

All non-git operations go through the `skillshare` CLI (`v0.19.x`, single Go binary).

| Task | Command |
|---|---|
| Inspect source / targets / tracked-repo state | `skillshare status` |
| Preview sync changes (no writes) | `skillshare sync --dry-run` |
| Sync skills to all targets | `skillshare sync` |
| Open the web dashboard | `skillshare ui` (defaults to http://127.0.0.1:19420) |
| Install a new skill from GitHub | `skillshare install <owner>/<repo>[/<subdir>]` |
| Update tracked external repos | `skillshare update --all` |
| Security audit (prompt injection / exfil scan) | `skillshare audit` |
| Commit + push source in one step | `skillshare push -m "msg"` |
| Pull + auto-resync targets | `skillshare pull` |

`skillshare sync` automatically writes a backup of each target before
modifying it: `%AppData%\skillshare\backups\<timestamp>\<target>\`. To roll
back a bad sync: `skillshare restore <target>`.

## When adding a new skill

1. Decide its category folder (`frontend/<framework>/`, `backend/`, `desktop/`, `web-dev/`, `utils/`). If none fit, prefer extending the structure to inventing flat siblings.
2. `skillshare new <name>` from inside that folder, **or** `skillshare install <repo>` (which writes to the source root — you may need to `git mv` it into a category afterward).
3. Run `skillshare sync --dry-run` to confirm the auto-flattened target name is what you expect.
4. Commit on `dev`, then FF-promote per the branch workflow above.

## When editing an existing skill

Edit files directly in their category-folder location. Because targets are
**symlinks** to this source (on Windows: NTFS junctions), changes are picked
up by every AI CLI tool the next time it reads its skills dir — no `sync`
required for edits to existing files. `sync` is only required when:

- Adding a new skill folder
- Removing/renaming a skill folder
- Changing `.skillignore`
- Switching a target's mode (symlink ↔ copy)

## Gotchas

- `.metadata.json` is **skillshare-managed** — do not hand-edit unless you understand the `tree_hash` + per-file `sha256` drift-detection mechanism. Wrong hashes cause `skillshare status` to flag the skill as drifted.
- `_elf-dev/`'s skills appear in `skillshare status` (currently 11 of them) but are NOT this repo's responsibility — fix them in `elf-express/org-skills` instead.
- The `skillshare/` folder at the root is the meta tool (CLI helper installed as a skill), kept in `.skillignore` so it doesn't get synced as a skill. Don't delete it — it's how the CLI bootstraps inside AI tool contexts.
- Line endings: Git is configured with `core.autocrlf` for Windows; new files written via LF will be normalized to CRLF in the working tree but stored as LF in the index. The `LF will be replaced by CRLF` warning on commit is harmless.
