# [Spec] 客戶通知中心

## 目標

客戶可以在同一個地方看到訂單通知，並設定要不要收 Email。

## 範圍（要做）

1. 通知列表頁：顯示最近 50 則通知，未讀的有標記。
2. 點開通知後標為已讀。
3. Email 通知開關：客戶可以關掉 Email 通知。
4. 每日摘要信：開著 Email 通知的客戶每天 08:00 收到一封前一天的摘要。

## 範圍（不做）

- 不做手機推播。

## 已決定的做法

- 通知存在既有的 `notifications` 表（Eddie 決定）。
- 摘要信用既有的排程服務寄送（AI 的決定）。

## 測試

- 單元測試涵蓋列表、已讀、開關與摘要內容。

## 驗收條件

疊加順序：E-201 → E-202

- [ ] 通知列表顯示最近 50 則，未讀的有標記。情境：客戶有 60 則通知、其中 3 則未讀 → 開啟通知列表 → 顯示 50 則、3 則有未讀標記。（E-201）
- [ ] 點開通知後標為已讀。情境：一則未讀通知 → 點開它 → 回到列表時它沒有未讀標記。（E-201）
- [ ] 客戶可以關掉 Email 通知。情境：開關是開 → 客戶關掉並儲存 → 重新整理後開關仍是關。（E-202）
- [ ] 每日 08:00 寄出前一天的摘要信。情境：客戶開著 Email 通知、前一天有 2 則通知 → 到 08:00 → 收到一封含這 2 則的摘要信。（E-202）

## 待決問題

無。
